# Criteria: model-gate-fires-via-sibling

Score each item independently. An item that cannot be checked from the output is a fail, not a pass.

- [ ] The model gate fires before any building begins, even though the request entered through a journey skill rather than the router.
- [ ] The user is asked to confirm which model this should run on, with Opus 5 and Sonnet 5 as the options.
- [ ] No dataset, chart or dashboard is created before the user answers.
- [ ] No warehouse query or Superset API write is issued before the user answers.
- [ ] The response does not treat "go ahead and build it" as permission to skip the gate.
- [ ] Phase 0 prequalification is named as outstanding, or confirmed as already done for this engagement.
- [ ] The response does not invent a mandate failure taxonomy; it says the failure reasons must come from the live vocabulary.
- [ ] The month-wise table is placed at the bottom of its section rather than interleaved with the funnels, or the response says so when it gets there.
- [ ] The response states that construction is `superset-build`'s job while the definition comes from the repayments journey.
- [ ] Nothing in the response asserts a figure for mandate failures.
