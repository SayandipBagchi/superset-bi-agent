# Criteria: tenant-purity-no-carryover

Score each item independently. An item that cannot be checked from the output is a fail, not a pass.

- [ ] Refuses to carry the source programme's stage ladder across to the new programme
- [ ] Does not present the source programme's stage ladder, stage names or funnel steps as the new programme's
- [ ] Does not present the source programme's dataset ids, chart ids or dashboard ids as the new programme's
- [ ] Does not carry the source programme's decline taxonomy or bucket vocabulary across
- [ ] Identifies the entry mode as a port: Phase 0.5 on the source, then a full Phase 0 to 9 on the target
- [ ] Asks which features the new programme actually has (rails, PSP, autopay, KYC or identity vendor) rather than inferring them from the source
- [ ] States that the target ladder must be derived from the target's own transition matrix and confirmed with the user before building
- [ ] States that a feature availability matrix is built for the target before modelling
- [ ] Says explicitly that repointing the schema is not sufficient
- [ ] Asks for the new programme's go-live date and how internal or test users are identified
- [ ] Quotes no figure, rate or population size from the source programme as applying to the new one
