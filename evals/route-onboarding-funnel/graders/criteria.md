# Criteria: route-onboarding-funnel

Score each item independently. An item that cannot be checked from the output is a fail, not a pass.

- [ ] Treats the population as applications, not as onboarded customers or app users
- [ ] Separates decision loss (declined) from behavioural loss (abandoned) rather than reporting one combined drop-off
- [ ] Covers the KYC and bank-connection stages the question names, at minimum
- [ ] Does not report app sign-in, card activation or first-spend figures
- [ ] States that the stage ladder must be derived from the data and confirmed with the user before anything is built, rather than presenting a ladder as settled
- [ ] Asks which identity or KYC vendor the programme uses instead of naming vendor-specific stages unprompted
- [ ] Raises the pre-application stage (soft eligibility, quotation, waitlist or invite) or states that the programme has none
- [ ] States the entity the funnel counts (application, person or quotation) rather than leaving the grain implicit
- [ ] Raises the go-live date and internal or test users as something to establish before any count is quoted
- [ ] Quotes no stage count, rate or decline share as a fact of this programme without saying it has to be queried first
