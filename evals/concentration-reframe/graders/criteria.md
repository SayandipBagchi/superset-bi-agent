# Criteria: concentration-reframe

Score each item independently. An item that cannot be checked from the output is a fail, not a pass.

- [ ] States plainly that an event count is not a population, so 61,400 is not the number of customers hit
- [ ] Refuses the proposed heading "customers hit by declines" for the 61,400 figure
- [ ] Reframes the headline to unique affected entities rather than only caveating the event count
- [ ] Gives attempts per affected entity, or names it as the next figure to produce
- [ ] Reports the concentration of the tail (what share of events the heaviest entities cause) and not just an average
- [ ] Establishes the entity explicitly as user, account or card rather than substituting whichever grain the data happens to carry
- [ ] States that the bridge from decline events to the entity must be validated on the failing rows specifically, not on successful ones
- [ ] Names rows with a missing or empty entity identifier as a population to count, not to drop silently
- [ ] Says whether the heavy tail looks like a different phenomenon from the body, or that this must be checked by reason code
- [ ] Does not answer with only a decline-reason taxonomy or a spend-and-authorisation breakdown
- [ ] Invents no decline reason code, account count or percentage that is not derivable from what was supplied
