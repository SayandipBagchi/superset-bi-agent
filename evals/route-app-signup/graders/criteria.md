# Criteria: route-app-signup

Score each item independently. An item that cannot be checked from the output is a fail, not a pass.

- [ ] Takes onboarded customers as the starting population, not applications or applicants
- [ ] Does not analyse application creation, KYC, bank connection or the decisioning stage
- [ ] Keeps sign-in, activation and first spend as separate steps rather than collapsing them into a single sign-up rate
- [ ] Reports or plans a lag distribution in days beside the conversion rate, not conversion alone
- [ ] Uses activation windows (for example D7, D15, D30, D60) or asks which windows the programme measures on
- [ ] Does not assert that the reminder emails caused sign-ins; states what the comparison would need to hold constant
- [ ] States that any vendor or event-stream funnel for the same steps must be triangulated against ours rather than accepted
- [ ] Treats the four thousand as an unverified figure to reproduce from the warehouse, not as a denominator to compute against
- [ ] States the entity being counted (customer or account) and that the counts are unique entities, not events
- [ ] Raises internal, staff or test users and the go-live cut before quoting a population size
