Use the `superset-bi-agent` skill, greenfield entry mode.

Run the model gate first — prompt for Opus 5 or Sonnet 5, say which you are on, and record the
choice — then work Phase 0 prequalification in order: operating mode and environment, programme
timeline and internal users, product artefacts, reference dashlets, audience and decision,
acquisition source, journey scope, definitions verbatim, funnel semantics, presentation and known
unknowns. Return the answers you have, the gaps, and the blocking questions, in that order. Stop at
the Phase 1 checkpoint; do not design dashlets yet.

Ask rather than assume. Confirm the environment and the schema empirically before reading a row
(G10), get the go-live date and any internal-user attribute in writing (G8), and ask about the
pre-application stage explicitly — it is the least consistent part of any engagement. Where the ask
is a port, profile the source suite but carry nothing across: the stage ladder, decline taxonomy,
rails, PSP and feature set are all derived fresh on the target.

Do not invent a stage ladder, a decline taxonomy, a vendor name or a metric definition, and do not
open another engagement's tenant file and treat it as a starting shape.
